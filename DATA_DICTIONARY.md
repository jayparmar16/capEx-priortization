# Data Dictionary: Output Files

This document explains the contents of the CSV files generated in the `data/` directory during the execution of the pipeline. Because the `data/` directory is ignored by Git, you will only see these files after running the pipeline locally.

## Data Source & API Integration

The base geographic data is scraped from the **OpenStreetMap Overpass API**.
* The script `src/fetch_properties.py` queries the Overpass API for nodes and ways tagged as `building=commercial`, `office`, or `retail` within the bounding boxes of Miami-Dade, Broward, and Polk counties.
* **Demographics (US Census API)**: Uses the FCC Area API to convert lat/lon to FIPS codes, then pulls real Median Household Income and exact Minority percentages via the US Census API.
* **Flood Risk (FEMA NFHL API)**: Queries the FEMA ArcGIS REST API to find the real flood zone for the property.
* **Important Note:** To ensure the pipeline works without requiring expensive commercial API keys or private Yardi/MRI access, the financial data (NOI, property value) and wind exposure are **synthetically generated** in `src/augment_data.py`. *However, the financial proxy is mathematically driven by the REAL Census income data to ensure a highly authentic distribution.*

## 1. `data/raw_properties.csv`

Generated by: `src/fetch_properties.py`

This file contains the raw, unmodified data fetched from the Overpass API.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | String | The unique OpenStreetMap identifier (e.g., `osm_123456`). |
| `lat` | Float | Latitude coordinate of the commercial building. |
| `lon` | Float | Longitude coordinate of the commercial building. |
| `county` | String | The county the property is located in (Miami-Dade, Broward, or Polk). |
| `building_type` | String | The OSM tag for the building (commercial, office, retail). |
| `name` | String | The name of the property (if available in OSM, otherwise a generic fallback). |

---

## 2. `data/portfolio_augmented.csv`

Generated by: `src/augment_data.py`

This file takes the raw properties and adds synthetic demographic, risk, and financial layers.

| Column | Type | Description |
| :--- | :--- | :--- |
| *(All columns from raw_properties.csv)* | | |
| `raw_income` | Float | REAL Median Household Income pulled from the US Census API. |
| `income_quartile` | Float | Census tract income bucketed into quartiles (1.0 = Lowest, 4.0 = Highest) for the dashboard. |
| `minority_pct` | Float | REAL percentage of minority residents in the tract, pulled from the US Census API. |
| `flood_zone` | String | REAL FEMA flood zone (`VE`, `AE`, or `X`) pulled from the FEMA NFHL API. |
| `wind_risk_mph` | Float | Simulated ASCE 7 wind exposure proxy (e.g., 120 mph inland vs 180 mph on the coast). |
| `property_value` | Float | Simulated property value. Mathematically driven by the REAL `raw_income` and county location. |
| `noi` | Float | Net Operating Income. Calculated as a simulated cap rate percentage of the property value. |
| `insurance_premium` | Float | Annual insurance cost. Calculated as a percentage of property value, heavily penalized for being in a `VE` flood zone. |

---

## 3. `data/portfolio_scored.csv`

Generated by: `src/agentic_scorer.py`

This file contains the output of the LangGraph multi-agent system, which ranks the properties based purely on the risk and financial data.

| Column | Type | Description |
| :--- | :--- | :--- |
| *(All columns from portfolio_augmented.csv)* | | |
| `physical_risk_score` | Float | A normalized score (0 to ~1.5) calculated by the Risk Assessor Agent based on `wind_risk_mph` and `flood_zone`. |
| `financial_exposure_score` | Float | A normalized score calculated by the Financial Analyst Agent based on `noi` and `insurance_premium`. |
| `final_priority_score` | Float | The combined score determining the overall ranking (60% Financial + 40% Physical Risk). |
| `baseline_rank` | Float | The rank of the property (1 is the highest priority). |
| `funded_baseline` | Boolean | `True` if the property falls in the top 30% of the `baseline_rank`. This represents the AI's "fund-first" recommendation. |

---

## 4. `data/portfolio_audited.csv`

Generated by: `src/audit_pipeline.py`

This file contains the output of the fairness audit. It adds the critical metric used to determine if the baseline scoring is justified.

| Column | Type | Description |
| :--- | :--- | :--- |
| *(All columns from portfolio_scored.csv)* | | |
| `minority_quartile` | String | The `minority_pct` column converted into discrete quartiles ('Low', 'Low-Mid', 'Mid-High', 'High') for easier grouping. |
| `risk_justified_prob` | Float | The probability that this property would be funded *if the decision was based strictly on physical risk* (`physical_risk_score`). Calculated using Logistic Regression. Comparing this to the actual `funded_baseline` rate reveals the unexplained gap. |

---

## 5. `data/portfolio_reranked.csv`

Generated by: `src/reranker.py`

This file contains the final output if the asset manager chooses to apply the Parity Guardrail.

| Column | Type | Description |
| :--- | :--- | :--- |
| *(All columns from portfolio_audited.csv)* | | |
| `temp_funded` | Boolean | An intermediate column used by the greedy swap algorithm during calculations. |
| `funded_reranked` | Boolean | The new "fund-first" list after the algorithm has swapped properties to ensure that selection rates across `income_quartile` fall within a 10% tolerance of the overall portfolio average. |
